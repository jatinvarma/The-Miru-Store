1. Introduction

In the contemporary digital age, the landscape of commerce has undergone a radical transformation. Electronic commerce, commonly known as e-commerce, has shifted from being a technological luxury to a fundamental cornerstone of global trade. Modern retail is no longer bound by geographic limitations, operational hours, or structural space. Instead, businesses operate continuously, offering products to a global consumer base. However, as the digital marketplace has matured, a new set of challenges has emerged. E-commerce web design has historically gravitated towards mass distribution, resulting in cluttered layouts, aggressive advertisements, multi-layered interfaces, and intrusive dark patterns designed to manipulate consumer behavior. These elements contribute to high cognitive overhead, decision fatigue, and a diminished aesthetic experience for the user.

The "MIRU Curated Objects Store" is designed as a direct response to this prevailing complexity. It is an editorial, full-stack e-commerce application built on a minimalist design philosophy. Rather than inundating the user with hundreds of options, banners, and promotional links, MIRU focuses on presenting a carefully selected list of unique lifestyle products, home accessories, apparel, and design objects. The architecture leverages a fast, lightweight stack, utilizing React for client-side interactions, Express.js for service routing, and SQLite for stable relational database transactions. The system is designed to provide zero-friction navigation, swift response times, and high visual clarity, enabling users to explore and acquire objects in a peaceful, elegant, and secure environment.

1.1 Objective of the Project

The primary objectives of the MIRU E-commerce Store project are defined as follows:

  • Aesthetic and Usability Objective: To construct a full-stack web application that rejects standard, cluttered retail templates in favor of a clean, serif-dominant, print-like editorial aesthetic. The user interface aims to balance whitespace and typography, minimizing distractions and allowing products to serve as the visual centerpieces.
  • Operational Efficiency Objective: To reduce the number of user interactions required to complete a transaction. The core system objective is to allow any user to search the catalog, add products to their cart, configure quantities, and complete the order checkout in fewer than three mouse clicks, avoiding the long redirects typical of traditional stores.
  • Stateless and Secure Session Objective: To implement a robust, secure authentication system utilizing JSON Web Tokens (JWT) and client-side storage, ensuring that the backend APIs remain stateless and protected against unauthorized lateral access. All sensitive user passwords must undergo irreversible encryption using the bcrypt hashing algorithm before database persistence.
  • Persistent Cart and Account Management: To provide a database-backed persistence layer for each user's shopping cart. This ensures that items added to a cart are preserved across multiple sessions and devices. It also supports a complete account dashboard displaying orders, order history details, and a wishlist system.
  • Low System Overhead: To establish a decoupled client-server architecture capable of running efficiently on low-cost virtual private servers (VPS) with restricted resources (e.g., 1 Core CPU, 512 MB RAM), avoiding the database latency and server overhead associated with large platforms like Magento or WooCommerce.

1.2 Scope of the System

The scope of the MIRU project is comprehensive, covering all layers of a full-stack e-commerce architecture. The application is divided into front-end user experience features, back-end service layers, and database management modules:

In-Scope Client Features:

  • Dynamic Catalog and Inventory Display: A fully responsive grid layout displaying curated objects. The view incorporates real-time client-side sorting by price points (ascending/descending), categorical filtration (Home, Kitchen, Accessories, Apparel), and free-text search queries.
  • Interactive Detail Modal: A custom-designed modal component that triggers on product selection, displaying product descriptions, stock levels, item tags, and a carousel of high-resolution images.
  • Sliding Cart Drawer: An overlay cart component that slides out from the right margin, allowing users to modify item quantities, view running subtotals, apply promotional coupons, and transition directly to the checkout form without leaving the current view.
  • Unified Account Dashboard: A user interface section where authenticated customers can manage their profiles, view detailed logs of past orders (including items purchased, shipping address, coupon savings, and checkout timestamps), and review their active wishlist.
  • Admin Panel Interface: A secure workspace for store administrators. Features include real-time platform statistics (total sales, user counts, order counts, active coupon counts), product inventory management (create, update, delete products, modify price, stock, and upload images), active order tracking, customer messages logs, and coupon management.

In-Scope Server Features:

  • Decoupled RESTful API Routers: Distinct endpoints handling user authentication, shopping carts, order checkouts, wishlist operations, and administrator updates.
  • Stateless JWT Validation Middleware: Interceptor logic designed to parse Bearer tokens, verify signatures, and populate user metadata in routing contexts.
  • Relational DB Operations: SQLite synchronization via high-performance 'better-sqlite3' driver execution.

Out of Scope:

  • Live Payment Gateway Integration: The system implements a mock checkout process with payment details simulation. Real-world Stripe, PayPal, or card authorization APIs are omitted to avoid regulatory compliance overhead.
  • Automated Shipping Logistics: Integrating real-time third-party shipping APIs (such as FedEx or DHL) for label generation and live location tracking is excluded.
  • Multi-Warehouse Inventory Control: The application supports single-source inventory fulfillment and does not support distributed multi-warehouse routing.

2. System Study

A crucial phase in software development is the study and analysis of existing systems in the domain. Understanding the standard design paradigms and architecture of active platforms allows developers to identify systematic failures, locate operational gaps, and design features that improve on current standards.

2.1 Existing System

Currently, the e-commerce landscape is dominated by large marketplaces (such as Amazon and eBay) and self-hosted platform structures (such as WooCommerce, Magento, and Shopify). These systems utilize traditional web design principles, focusing on maximum data density. When a user navigates to an existing system, the view is occupied by multiple layout grids, flashing promotional banners, sponsored product carousels, customer reviews, side menus, and pop-up notifications. The primary architecture of these systems is typically server-side rendering (SSR) or complex client-side bundles loaded with trackers, analytics packages, marketing tags, and customer support widgets. Databases are typically large SQL clusters (MySQL, PostgreSQL) or NoSQL document stores (MongoDB) hosted on separate servers, communicating over network sockets.

2.2 Drawbacks of Existing System

An in-depth analysis of these existing e-commerce systems reveals several significant drawbacks:

  • High Cognitive Overhead (UX): The excessive amount of visual information, recommendations, and advertisements overwhelms the user. This clutter makes it difficult to focus on the products, leading to decision fatigue and an unpleasant shopping experience.
  • Performance Degradation: The inclusion of third-party scripts, tracking pixels, and large assets makes existing sites slow. These sites often require several megabytes of data transfer per page load, causing latency and friction on mobile devices or slower networks.
  • Friction in Checkout Flow: Traditional checkouts often require multiple redirects, loading steps, and account registration forms. Every extra page load increases the likelihood of cart abandonment.
  • High Deployment and Maintenance Costs: Systems like Magento or WooCommerce require substantial server resources to operate. They need separate databases, caching layers (Redis, Memcached), and web server configurations, making deployment complex and expensive.
  • Security Risks: Relying on many third-party plugins (especially in platforms like WordPress/WooCommerce) increases the attack surface. Vulnerabilities in outdated plugins frequently expose customer data and compromise credentials.

2.3 Proposed System

The proposed "MIRU Curated Objects Store" is designed to address these limitations. MIRU focuses on a minimalist, single-page application (SPA) design using a modern, lightweight technology stack. It uses React on the frontend and an Express.js API on the backend, with SQLite for data storage. All interface elements are styled using custom CSS, avoiding the layout clutter of traditional sites. By eliminating third-party trackers, large page layouts, and multi-step checkouts, MIRU provides a clean, fast user experience. The entire checkout process is completed in a single modal drawer without page reloads.

2.4 Advantages of the Proposed System

The MIRU system offers several key advantages:

  • Minimalist Editorial Aesthetic: Designed using serif typography and generous white space, the platform reads like a modern print catalog, highlighting the products.
  • Fast Response Times: By using a client-side React SPA and a local SQLite database, API responses compile in under 50ms, providing near-instant transitions.
  • Seamless Checkout Experience: The checkout form is built directly into the cart drawer. Users can complete transactions on the same page, reducing cart abandonment.
  • Secure Architecture: Uses secure bcrypt hashing for passwords and stateless JWT verification for APIs, preventing common security vulnerabilities.
  • Simple Deployment: The database is self-contained in a local SQLite file ('shop.db'). The entire application can be deployed on a minimal VPS with a single command.

5. System Implementation and Testing

This chapter covers the implementation details, directory structures, architectural patterns, and testing protocols used to verify the application's functionality.

5.1 System Implementation

The MIRU project is implemented as a decoupled client-server web application. The frontend uses React with hooks and state managers to handle the interface dynamically, while the backend uses Express.js with SQLite to manage APIs and data storage.

Key Design Patterns Implemented:

  • Decoupled Routing: The entry file 'server.js' acts as a request router, delegating routes to files in 'src/routes/' to keep code clean and modular.
  • Middleware Interceptor Pattern: Security is handled by middleware functions. Sensitive API requests are intercepted to check and decode the JWT token before proceeding.
  • Single File Database: Uses SQLite ('shop.db') for simple deployment and fast local database operations.

59// Helpers for validation
60const getCardBrand = (number) => {
61  const clean = number.replace(/\D/g, '');
62  if (/^4/.test(clean)) return 'visa';
63  if (/^(5[1-5]|2[2-7])/.test(clean)) return 'mastercard';
64  if (/^(60|65|81|82)/.test(clean)) return 'rupay';
65  if (/^3[47]/.test(clean)) return 'amex';
66  return 'unknown';
67};
68
69const validateLuhn = (number) => {
70  const clean = number.replace(/\D/g, '');
71  if (!clean || clean.length < 13) return false;
72  let sum = 0;
73  let shouldDouble = false;
74  for (let i = clean.length - 1; i >= 0; i--) {
75    let digit = parseInt(clean.charAt(i), 10);
76    if (shouldDouble) {
77      digit *= 2;
78      if (digit > 9) digit -= 9;
79    }
80    sum += digit;
81    shouldDouble = !shouldDouble;
82  }
83  return sum % 10 === 0;
84};
85
86const validateExpiry = (expiry) => {
87  const match = expiry.match(/^(\d{2})\s*\/\s*(\d{2})$/);
88  if (!match) return false;
89  const month = parseInt(match[1], 10);
90  const year = parseInt('20' + match[2], 10);
91  if (month < 1 || month > 12) return false;
92  
93  const now = new Date();
94  const currentMonth = now.getMonth() + 1;
95  const currentYear = now.getFullYear();
96  
97  if (year < currentYear) return false;
98  if (year === currentYear && month < currentMonth) return false;
99  return true;
100};
101
102const fmtCard = (v, brand) => {
103  if (!v) return '';
104  const clean = v.replace(/\D/g, '');
105  if (brand === 'amex') {
106    const parts = [];
107    if (clean.length > 0) parts.push(clean.slice(0, 4));
108    if (clean.length > 4) parts.push(clean.slice(4, 10));
109    if (clean.length > 10) parts.push(clean.slice(10, 15));
110    return parts.join(' ');
111  } else {
112    return clean.slice(0, 16).replace(/(.{4})/g, '$1 ').trim();
113  }
114};

6. Conclusion and Future Enhancement

6.1 Conclusion

The "MIRU Curated Objects Store" project demonstrates that e-commerce platforms can be designed with a clean, minimalist aesthetic without sacrificing essential features. By using lightweight, modern technologies—React for responsive user interfaces, Express.js for simple API routing, and SQLite for stable data storage—the platform provides a fast, zero-friction shopping experience.

The development process met all primary requirements, including secure user authentication with JWT, persistent cart management, custom coupon codes, and a secure admin panel. Additionally, print-friendly CSS rules were implemented, ensuring the application and its reports format cleanly when printed or saved as PDFs.

6.2 Future Enhancement

While the initial version is complete and functional, the platform is structured to support future updates:

  • Real Payment Gateway Integration: Replace mock checkout fields with real payment processors like Stripe or PayPal for secure online payments.
  • Cloud Media Storage: Shift image storage from the local server filesystem to cloud services like Amazon S3 or Cloudinary to improve scalability.

  • Automated Notifications: Integrate email notification services (such as Nodemailer or SendGrid) to send order confirmations and newsletters automatically.
  • Search Engine Optimization (SEO) & SSR: Implement server-side rendering (using frameworks like Next.js) to improve SEO and index page load times.

Appendix I: Quick-Start Configuration & Deployment Guide

Follow these steps to set up and run the MIRU project locally:

Prerequisites:

  • Node.js (version 16.14.0 or greater) installed on the host operating system.
  • npm package manager (installed automatically with Node.js).

Installation Instructions:

# 1. Clone or copy project files into a folder
# 2. Navigate to the backend directory and install dependencies
cd backend
npm install

# 3. Navigate to the frontend directory and install dependencies
cd ../frontend
npm install

Running the Platform:

You can run both servers together or start them in separate terminals:

# Running together using start script:
cd ..
./start.sh   # On Linux/macOS
start.cmd    # On Windows

# Running separately:
# Terminal 1 (Backend API):
cd backend
node server.js

# Terminal 2 (Frontend Static Server):
cd frontend
npm run dev

Once started, open your web browser and navigate to http://localhost:3000 to access the store.
